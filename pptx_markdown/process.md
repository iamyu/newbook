流程框架（高阶流程）的意义与关键要素



* <span style="color:#002960"> __流程框架的意义__ </span>
  * <span style="color:#000000"> __对业务：__ </span>  <span style="color:#000000">作为</span>  <span style="color:#000000"> __结构化蓝图__ </span>  <span style="color:#000000">，指导流程体系梳理诊断、聚焦流程优化重点、并帮助定义运营标准化</span>  <span style="color:#000000">/</span>  <span style="color:#000000">集约化的分布与程度</span>
  * <span style="color:#000000"> __对组织：指导组织架构设计__ </span>  <span style="color:#000000">，即先定义“干什么”、再定义“由谁干”，帮助企业建立</span>  <span style="color:#000000"> __流程化组织__ </span>
  * <span style="color:#000000"> __对__ </span>  <span style="color:#000000"> __IT__ </span>  <span style="color:#000000"> __：__ </span>  <span style="color:#000000"> __对IT架构的建设提供关键指导__ </span>  <span style="color:#000000">，尤其是应用系统架构</span>  <span style="color:#000000">\(</span>  <span style="color:#000000">AA\)</span>  <span style="color:#000000">及数据架构</span>  <span style="color:#000000">\(</span>  <span style="color:#000000">DA\)</span>  <span style="color:#000000">，即先定义“干什么”、再定义“有哪些数据支持和系统支持</span>  <span style="color:#000000">”</span>
* <span style="color:#002960"> __好的流程框架的__ </span>  <span style="color:#002960"> __关键要素__ </span>
  * <span style="color:#000000"> __业务覆盖全面：__ </span>
    * <span style="color:#000000">覆盖企业运营的不同层次（如总部、分子公司）</span>
    * <span style="color:#000000">覆盖业务运营的不同领域（如业务价值链、管理管控职能）</span>
  * <span style="color:#000000"> __体系结构严谨：__ </span>  <span style="color:#000000">如流程模块之间有必要的层级与逻辑关系，流程模块之间全覆盖而没有交集</span>
  * <span style="color:#000000"> __反映业务逻辑__ </span>  <span style="color:#000000">：</span>
    * <span style="color:#000000">价值链的业务总体顺序与关系</span>
    * <span style="color:#000000">运营领域内的生命周期</span>
    * <span style="color:#000000">业务开展的逻辑方法</span>
  * <span style="color:#000000"> __体现业务差异__ </span>  <span style="color:#000000">：对于业务价值链流程，各种业务场景模式下需要不同的业务能力</span>  <span style="color:#000000">/</span>  <span style="color:#000000">流程模块</span>
  * <span style="color:#000000"> __逻辑__ </span>  <span style="color:#000000">上的</span>  <span style="color:#000000"> __工作模块__ </span>
  * <span style="color:#000000">主要回答“干什么”的问题</span>
  * <span style="color:#000000">工作模块</span>  <span style="color:#000000"> __操作方式__ </span>  <span style="color:#000000">的</span>  <span style="color:#000000"> __具体__ </span>  <span style="color:#000000">描述</span>
  * <span style="color:#000000">主要回答“怎么干、谁来干、什么时候干、用什么干”的问题</span>
  * <span style="color:#000000">组成</span>  <span style="color:#000000"> __流程框架__ </span>  <span style="color:#000000">，指导具体流程的建设与设置</span>
  * <span style="color:#000000">作为</span>  <span style="color:#000000"> __行动手册__ </span>  <span style="color:#000000">，具体指导日常运营的过程</span>
  * <span style="color:#000000">对业务</span>  <span style="color:#000000"> __覆盖全面__ </span>
  * <span style="color:#000000"> __结构严谨__ </span>  <span style="color:#000000">：流程模块有必要的层级与逻辑关系，而全覆盖没有交集</span>
  * <span style="color:#000000"> __反映业务逻辑__ </span>
  * <span style="color:#000000">不直接体现现有组织架构与职责划分，但有指导意义</span>
  * <span style="color:#000000">具有</span>  <span style="color:#000000"> __流程业务目的__ </span>  <span style="color:#000000">、</span>  <span style="color:#000000"> __输入、输出、关键业务控制点、业务逻辑等__ </span>  <span style="color:#000000">信息</span>
  * <span style="color:#000000">对高阶流程的细化</span>
  * <span style="color:#000000">根据详细流程的范围，对应</span>  <span style="color:#000000"> __不同层级__ </span>  <span style="color:#000000">的流程模块</span>
  * <span style="color:#000000">本身是一个流程图，具有具体的工作</span>  <span style="color:#000000"> __过程__ </span>  <span style="color:#000000">与</span>  <span style="color:#000000"> __职责__ </span>  <span style="color:#000000">定义，可作为</span>  <span style="color:#000000">SOP</span>

流程设计方法论－自上而下及自下而上方法

|  | __自上而下（__  __Top\-down __  __）__ | __自下而上（__  __Bottom\-up __  __）__ |
| :-: | :-: | :-: |
| __方法__ | 首先构建流程全貌，然后层层分解到细节流程 | 从细节流程入手，然后挑选、合并进行处理，然后生成上一级流程 |
| __优点__ | 能够建立流程体系的全貌，容易检验和修订可以避免流程的重复、重叠和不能进行连接最大限度的保证了流程的共享和复用 | 建立基于实际的流程应用 |
| __不足__ | 需要有清晰的参考框架作为输入可能会与原有流程有较大差异 | 不能看到流程的全貌通过底层合并非常困难，很难形成完整的流程体系 |
| __总结__ | 适合于全新业务单元的流程建立 | 适合于基于现有流程（AS\-IS）建立体系结构 |

<span style="color:#000000"> __项目的建模方法：从上而下建立__ </span>  <span style="color:#000000"> __流程高阶框架__ </span>  <span style="color:#000000"> __，自下而上进行流程匹配。兼顾流程的完整性和业务场景的选择。__ </span>
